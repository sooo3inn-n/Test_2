# AI 서비스 기획 강의용 웹앱 사용자 흐름과 화면

강사가 브라우저에서 **AI 고객 문의 답변 도우미** 사례를 열어 프로젝터나 화면 공유로 시연한다. 수강생은 공유 화면을 보며 네 가지 기획 결정을 따라간다. 화면에는 수업용 가상 문의, 가상 반품 정책, 미리 준비한 AI 출력 예시를 사용한다.

## 공통 화면 구성

| 영역 | 표시 내용 |
| --- | --- |
| 상단 | 사례명과 화면 제목을 표시한다. 네 단계에는 ‘1 / 4’ 형식으로 현재 위치를 표시하고, 마지막 화면의 제목은 ‘요약’으로 표시한다. |
| 본문 | 핵심 문장을 먼저 보여주고, 아래에 작업 흐름, 문의 예시 또는 검증 방법을 배치한다. |
| 하단 | 현재 화면에서 사용할 수 있는 이동 버튼을 표시한다. |

1280 × 720 브라우저 뷰포트에서 제목, 핵심 문장, 이동 버튼을 가로 스크롤 없이 볼 수 있게 배치한다. Tab으로 이동 버튼에 접근하고 Enter 또는 Space로 실행할 수 있게 한다. 포커스가 있는 버튼은 시각적으로 구분한다.

## 화면별 상세

### 1. 사용자와 문제 · US-04

**핵심 문장** — 상담원은 반복되는 반품 문의마다 정책을 찾아 답변을 작성한다.

- 기존 처리 흐름을 ‘문의 확인 → 반품 정책 검색 → 답변 작성’으로 표시한다.
- 정책 검색과 답변 작성이 반복되는 지점임을 강조한다.
- 강의 질문 · 누구의 어떤 작업을 줄이려는가?

### 2. AI의 역할 · US-05

**핵심 문장** — AI는 고객 문의와 정책을 바탕으로 답변 초안과 근거를 보여준다.

- **고객 문의** · “3일 전에 받았고 아직 개봉하지 않았어요. 반품되나요?”
- **적용 정책** · 미개봉 상품은 수령 후 7일 이내에 반품을 신청할 수 있다.
- **답변 초안** · “미개봉 상품은 수령 후 7일 이내에 반품을 신청할 수 있습니다.”
- 문의·정책·초안을 나란히 배치하고, 초안이 참조한 정책 문구를 확인할 수 있게 한다. 상담원이 초안을 검토한 뒤 발송한다는 점을 함께 표시한다.
- 강의 질문 · AI는 어떤 입력을 받아 무엇을 돌려주는가?

### 3. 실패 시 대응 · US-05

**핵심 문장** — 필요한 정보가 빠져 있으면 AI가 확인할 항목을 표시하고 상담원이 판단한다.

- **고객 문의** · “지난주에 받았는데 반품되나요?”
- **AI 출력 예시** · “확인 필요 — 정확한 수령일과 개봉 여부가 필요합니다.”
- **상담원 조치** · 정확한 수령일과 개봉 여부 확인 → 반품 가능 여부 판단 → 최종 답변 발송.
- 강의 질문 · 이 문의에서 상담원이 직접 확인할 정보는 무엇인가?

### 4. 효과 검증 · US-06

**핵심 문장** — 같은 문의를 수동 방식과 AI 보조 방식으로 처리해 시간과 정책 준수 여부를 비교한다.

| 지표 | 화면에 표시할 기준 |
| --- | --- |
| 소요 시간 | 문의를 연 시점부터 발송 가능한 답변을 확정한 시점까지 걸린 시간 |
| 정책 위반율 | 검토한 최종 답변 중 정책을 위반한 답변의 비율 |

- 두 방식에 같은 정상 문의와 추가 확인이 필요한 문의를 사용한다.
- 강의 질문 · 처리 시간이 줄더라도 정책 위반율이 높아지면 어떤 결정을 내려야 하는가?

### 요약 · US-07

사용자 문제, AI의 역할, 상담원의 역할, 검증 방법을 한 화면에서 복습한다.

| 기획 결정 | 요약 문구 |
| --- | --- |
| 사용자 문제 | 반복되는 정책 검색과 답변 작성에 시간이 걸린다. |
| AI의 역할 | 정책을 근거로 답변 초안을 만들고, 정보가 부족하면 확인 항목을 표시한다. |
| 상담원의 역할 | 필요한 정보를 확인하고 최종 답변을 검토해 발송한다. |
| 검증 방법 | 같은 문의의 처리 시간과 정책 위반율을 비교한다. |

강사는 수강생에게 AI가 맡는 일, 상담원이 확인하는 일, 효과를 평가할 지표를 사례에 근거해 설명하도록 묻는다.

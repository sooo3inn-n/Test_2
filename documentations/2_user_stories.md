# AI 서비스 기획 강의용 웹앱 사용자 스토리

첫 버전에서는 강사가 **AI 고객 문의 답변 도우미** 사례를 화면에 공유하고 조작한다. 수강생은 준비된 가상 문의와 AI 출력 예시를 보며 기획 결정을 따라간다.

관련 문서 · [원페이저](0_one_pager.md) · [PRD](1_product_requirements_document.md)

## 강사

### US-01 · 사례를 열고 진행 위치 확인하기

강사로서 수업 중 데모를 바로 시작하고, 설명 중 현재 위치를 확인하고 싶다.

**완료 기준**

- 앱을 열면 첫 단계인 ‘사용자와 문제’가 표시된다.
- 각 단계에 단계 이름과 전체 네 단계 중 현재 위치가 표시된다. 마지막 화면에는 ‘요약’ 제목이 표시된다.

### US-02 · 설명 순서 조절하고 다시 시작하기

강사로서 수업 흐름에 맞춰 설명을 이어가거나 이전 사례 화면으로 돌아가고, 다음 수업에서 처음부터 다시 시연하고 싶다.

**완료 기준**

- ‘다음’을 누르면 문제 → AI의 역할 → 실패 시 대응 → 효과 검증 → 요약 순서로 이동한다.
- 둘째 단계부터 ‘이전’을 누르면 직전 화면으로 돌아간다. 요약에서 ‘이전’을 누르면 효과 검증 화면으로 돌아간다.
- 첫 화면에서 이전 이동은 불가능하고, 요약 화면에서 다음 이동은 불가능하다.
- 요약 화면에서 ‘처음부터’를 누르면 첫 단계로 돌아간다.

### US-03 · 공유 화면에서 읽기 쉽게 시연하기

강사로서 프로젝터나 화면 공유로 핵심 내용을 보여주면서 키보드로도 화면을 넘기고 싶다.

**완료 기준**

- 1280 × 720 브라우저 뷰포트에서 각 화면의 제목, 핵심 문장, 이동 버튼을 가로 스크롤 없이 볼 수 있다.
- Tab으로 사용 가능한 이동 버튼에 접근할 수 있고, Enter 또는 Space로 실행할 수 있다. 포커스가 있는 버튼은 시각적으로 구분된다.

## 수강생

### US-04 · 상담원이 겪는 문제 파악하기

수강생으로서 기존 문의 처리 과정을 보고, AI 서비스가 어떤 작업을 개선하려는지 설명하고 싶다.

**완료 기준**

- 화면에 문의 확인 → 정책 검색 → 답변 작성 순서가 표시되고, 반복되는 정책 검색과 답변 작성을 구분할 수 있다.

### US-05 · AI가 맡는 일과 상담원이 확인하는 일 구분하기

수강생으로서 정상 문의와 추가 확인이 필요한 문의를 보며 AI에 맡길 일과 사람이 판단할 일을 구분하고 싶다.

**완료 기준**

- 정상 예시에서 고객 문의, 가상 반품 정책, 미리 작성한 답변 초안이 구분된다. 초안이 어떤 정책 문구를 근거로 삼는지 확인할 수 있다.
- 추가 확인 예시에서 정확한 수령일과 개봉 여부가 필요하다는 점을 확인할 수 있다.
- 상담원이 초안을 검토하거나 부족한 정보를 확인한 뒤 최종 답변을 발송하는 흐름이 표시된다.

### US-06 · 효과를 검증하는 방법 설명하기

수강생으로서 AI 보조 방식이 상담 업무에 도움이 되는지 판단할 비교 방법과 지표를 알고 싶다.

**완료 기준**

- 효과 검증 화면에서 동일한 정상 문의와 추가 확인 문의를 수동 방식과 AI 보조 방식으로 처리해 비교하는 방법을 설명한다.
- 소요 시간은 문의를 연 시점부터 발송 가능한 답변을 확정한 시점까지로 표시한다. 정책 위반율은 검토한 최종 답변 중 정책을 위반한 답변의 비율로 표시한다.

### US-07 · 사례의 기획 결정 복습하기

수강생으로서 수업 끝에 기획 결정을 한눈에 확인하고, 사례를 바탕으로 설명하고 싶다.

**완료 기준**

- 요약 화면에 사용자 문제, AI의 역할, 상담원의 역할, 효과 검증 방법이 모두 표시된다.
- 수업에서 강사가 질문했을 때 수강생이 AI가 맡는 일, 상담원이 확인하는 일, 효과를 평가하는 지표를 사례에 근거해 설명할 수 있는지 확인한다.
